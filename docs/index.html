The assignment

Implement a Lark LALR(1) grammar for BibTeX citations, including standard entry types, nested braces, special characters and LaTeX commands. Verify it with the supplied tests, then integrate it with SynCode and generate citations using at least three different prompts.

The required deliverables are bibtex.lark and bibtex_syncode.py. This console, additional parser cases, boundary measurements and captured token traces support inspection of that implementation.

Local model: Qwen2.5-0.5B-Instruct, running on the CPU from downloaded model files. BibTeX, Lark, SynCode and Qwen are existing tools; this project supplies the citation grammar and integration/evaluation code.

How it works: The Python script loads the same grammar into Lark and SynCode. Qwen scores possible next tokens, SynCode filters the choices, and Lark checks the resulting text. The Qwen and SynCode steps repeat during generation.

Qwen → SynCode repeats for each generated token. Lark independently checks the completed response.

Try a citation

    
@book{rivera2025,
  author = {Alex Rivera},
  title = {Understanding {AI}},
  year = 2025
}

    

    
book is the entry type; rivera2025 is its citation key. Fields use name = value and commas separate them. The title contains an inner braced group around AI, which can protect its capitalization in BibTeX. This parser recognizes the structure; it does not typeset the bibliography.

    
braced: "{" (text | "\"" | braced)* "}"

    
The braced rule refers to itself, allowing nested groups. Paste the example below and predict acceptance. Remove the entry's final closing brace and predict rejection. Changing the year to another number still passes syntax validation.

Each input has an expected acceptance or rejection. The cases are reproducible from evaluate_bounds.py; they are not all individually handwritten.

    
Each case is parsed three times and its median time is recorded. Categories group the behavior being checked. Measured scale increases nested-group depth, number of entries or field-value length. The character column is the size of the full input. Passing all selected cases does not establish perfection or complete coverage.
